01 / The three layers

Clear roles.
Connected infrastructure.

Three independent layers, each with a defined responsibility. Start with any one; the architecture is designed to compose.

01

Persistent State

State that grows without bound. At the 100M development operating point, ExergyNet stores approximately 101 million estimated state tokens — without delivering them all to the model at once.

N ≈ 101,152,694 tokens
02

Bounded Context

Relevant state, not all state. ExergyNet selects and delivers what matters from the persistent store, keeping the model's working context bounded regardless of how much is stored.

K = 800 median tokens / query
03

Independent Authority

A model's proposal is not permission. In a reported live environment, a deterministic authority layer rejected an adversarial instruction that the reasoning model had accepted.

Proposal ≠ Execution
02 / How it works

Four layers.
Each independent.

Persistent state, context delivery, model reasoning, and execution authority operate as separate concerns. Each layer does exactly one thing.

The separation between N (what is stored) and K (what is delivered) is the core architectural property. The separation between model reasoning and execution authority is the core security property.

01

Persistent State

N ≈ 101M tokens stored

Content-addressed storage for state, evidence, and identity. Grows with the system. Never delivered in full to the model.

02

Context Delivery

K = 800 median tokens

Bounded context retrieved per query. Relevant evidence selected from the persistent store and delivered to the model's working context window.

03

Model Reasoning

REASONING LAYER

The model reasons over the delivered context and proposes a response or action. Proposal is not execution. Reasoning does not have authority.

04

Authority Gate

INDEPENDENT CONTROL

Consequential actions are evaluated against an independent authorization layer, separate from model reasoning. Allow or deny based on policy, not inference.
