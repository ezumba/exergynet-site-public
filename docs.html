Local memory quickstart

Get a persistent memory node running locally with your MCP client in minutes. The Vanguard Memory Node is free, open source, and stores everything on your own machine — no cloud account required.

What this sets up: A local MCP server that gives any compatible agent persistent memory — store, search, and retrieve across sessions. Tested with Claude Desktop and standard MCP stdio transport.

Prerequisites

Before you begin, confirm you have:

✓
Node.js 18 or later Required to run the memory node server. nodejs.org ↗
✓
An MCP-compatible client Claude Desktop, or any client implementing the Model Context Protocol stdio transport.
✓
Write access to your home directory The memory node stores its vault in ~/.vanguard/local_vault/ by default.
✓
ExergyNet account Required for API access and cloud features. Create your account at portal.exergynet.org ↗

Install the memory node

Install the Vanguard Memory Node globally using npm:

Terminal 
npm install -g @lnes/vanguard-memory-node

Verify the installation:

Terminal 
vmn --version

Source and issue tracking: github.com/ezumba/vanguard-memory-node ↗

Connect to your MCP client

Add the memory node as an MCP server in your client's configuration file. Choose your environment:

Config file ~/Library/Application Support/Claude/claude_desktop_config.json
JSON 
{
  "mcpServers": {
    "vanguard-memory": {
      "command": "node",
      "args": ["/usr/local/lib/node_modules/@lnes/vanguard-memory-node/dist/index.js"]
    }
  }
}

If Node.js was installed via nvm or Homebrew, the path to node_modules may differ. Run npm root -g to confirm the global path.

Config file %APPDATA%\Claude\claude_desktop_config.json
JSON 
{
  "mcpServers": {
    "vanguard-memory": {
      "command": "node",
      "args": ["C:\\Users\\YOUR_USER\\AppData\\Roaming\\npm\\node_modules\\vanguard-memory-node\\dist\\index.js"]
    }
  }
}

Replace YOUR_USER with your Windows username. Run npm root -g in a command prompt to confirm the path.

Config file %APPDATA%\Claude\claude_desktop_config.json
JSON 
{
  "mcpServers": {
    "vanguard-memory": {
      "command": "node",
      "args": ["/home/YOUR_USER/node_modules/@lnes/vanguard-memory-node/dist/index.js"]
    }
  }
}

When running Claude Desktop on Windows with the memory node installed inside WSL2, Claude Desktop's config must point to the WSL2 path. The command key must resolve to the WSL2 Node.js binary.

Store your first memory

Once your MCP client connects to the memory node, you have access to the vmn_ingest tool. Use it to store any text as a persistent memory shard.

In Claude Desktop, ask your model to run:

Natural language prompt 
Store a memory: "This project uses TypeScript. All API responses follow the shape {data, error, meta}."

The model will call vmn_ingest and return the shard's SHA-256 hash:

Tool output 
Stored · sha256:4a7f9b2e1c8d3f6a5e0b7c4d1e9f2a3b8c5d0e7f4a1b6c3d8e5f2a9b4c1d6e

To verify the memory persists, start a new Claude Desktop session and ask:

Natural language prompt 
What do you know about this project's API response shape?

The model will call vmn_search, retrieve the stored shard, and answer from it — without that information being in the system prompt or conversation history.

Common usage patterns

Accumulate project context

Store facts as you discover them. The memory node's BM25 index retrieves relevant shards on each query — the model receives only what is relevant, not the entire vault.

Prompts 
Remember: the database is PostgreSQL 15, schema is "prod".
Remember: the deployment target is AWS us-east-1, service: exn-api.
Remember: authentication uses JWT RS256, public key rotates every 30 days.

Retrieve on demand

At the start of a new session, ask the model to load context before beginning work:

Prompts 
Search your memory for anything relevant to the authentication system.
Recall everything you know about the deployment setup.

Cross-session continuity

At the end of a session, ask the model to store a summary of what changed:

Prompt 
Store a session summary: what we changed today, what's blocked, and what's next.

Tools reference

The Vanguard Memory Node exposes the following MCP tools:

Tool Purpose Key parameters
vmn_ingest Store text as a persistent memory shard content (string)
vmn_search BM25 keyword search over all shards query (string), limit
vmn_recall Retrieve a shard by SHA-256 hash shard_id (string)
vmn_inspect Show metadata for a specific shard shard_id (string)
vmn_list List stored shards (most recent first) limit
vmn_stats Vault statistics (count, index status) —
vmn_delete Delete a shard by hash shard_id (string)
vmn_rebuild_index Rebuild the BM25 search index —

Configuration

The memory node reads from environment variables passed through the MCP server configuration:

Variable Default Description
VMN_VAULT_DIR ~/.vanguard/local_vault Directory where shards and index are stored
VMN_MAX_RESULTS 10 Maximum results returned by vmn_search
VMN_INDEX_AUTO_REBUILD true Rebuild index automatically after ingest

To set a custom vault path in Claude Desktop config:

JSON 
{
  "mcpServers": {
    "vanguard-memory": {
      "command": "node",
      "args": ["/usr/local/lib/node_modules/@lnes/vanguard-memory-node/dist/index.js"],
      "env": {
        "VMN_VAULT_DIR": "/Users/YOUR_USER/my-project-vault"
      }
    }
  }
}
