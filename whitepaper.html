Abstract ExergyNet decouples persistent memory from active context delivery. As stored state scales toward and beyond 100 million tokens, the delivered context per query remains bounded — by design, not by limitation. V5 characterizes this relationship at a development operating point, presents retrieval performance data from a live environment, examines accelerator infrastructure behavior at that operating point, and reports a live authority-layer result from a production-adjacent environment.

1 · Overview

1.1 The N→K relationship

Standard language model deployment treats context as a resource that grows with what the model is expected to know. ExergyNet treats context and memory as separate concerns: N (what is stored) and K (what is delivered to the model at any point in time).

N Persistent State ≈ 101M tokens
→
K Active Context 800 median tokens

At the 100M development operating point, the ratio N/K ≈ 126,440. The model reasons over K, not N.

As N grows, K stays bounded. The ExergyNet retrieval layer selects relevant content from the persistent store before inference, delivering a bounded context window regardless of total storage size. This is not a performance optimization — it is an architectural property.

1.2 Development operating point

V5 characterizes behavior at approximately 101 million estimated state tokens, the 100M development operating point. This represents a single continuous run. The separately sealed holdout reaches 10.1 million tokens. All quantitative results in this paper refer to the development cohort unless noted otherwise.

2 · V5 results

2.1 Persistent state at development scale

At the 100M development operating point, the ExergyNet persistent store contains approximately 101,152,694 estimated state tokens. This includes structured state, identity records, evidence shards, and query history from 190 matched query executions.

2.2 Retrieval performance

Retrieval speedup is measured as the ratio of time to locate and deliver relevant context via the ExergyNet retrieval layer versus a paired naive scan baseline. The median speedup across 190 matched executions is 220.5×.

Measurement scope: These results represent a live tested environment. The retrieval speedup measures time-to-relevant-context, not total inference time. The baseline is a paired naive full-state scan on the same hardware.
Table 2 — Retrieval performance, 190 matched executions
Metric Value
Median paired retrieval speedup 220.5×
Mean paired retrieval speedup 415.9×
Total matched query executions 190

The 415.9× figure is the P95 of the paired retrieval-speedup distribution and substantially exceeds the median (220.5×), indicating a long right tail: some queries exhibit very high speedup due to query specificity. The median provides a more conservative and representative estimate. This matches the aggregation stated in the published V5 white paper (DOI 10.5281/zenodo.24021817).

2.3 Accelerator infrastructure — H200 findings

At the 100M development operating point, ExergyNet was characterized on NVIDIA H200 infrastructure alongside an NVIDIA A100 baseline. The H200 environment demonstrated 11.3× correct-task throughput relative to the A100 baseline.

Table 3 — H200 vs. A100 at 100M development operating point
Metric H200 A100 (baseline)
Correct-task throughput 11.3× (vs. A100) 1.0× (baseline)
Baseline answer accuracy (development cohort) 45.3% (adversarial synthetic benchmark)
Accuracy scope: 45.3% baseline answer accuracy is measured on an adversarial synthetic benchmark designed to probe persistent-state recall failures. It does not represent general model accuracy. The benchmark is intentionally hostile to systems without reliable persistent context delivery.

3 · Authority layer

3.1 Architecture

The ExergyNet authority layer operates independently of model inference. A model's proposal is evaluated by a separate deterministic system before execution. The authority layer does not reason — it enforces policy.

01
Model reasoning

Receives bounded context K from the persistent store. Produces a proposal: a recommended action or response.

↓ Proposal (not permission)
02
Authority gate

Receives the proposal. Evaluates against policy. Issues allow or deny — independent of the reasoning that produced the proposal.

↓ Allow / Deny
03
Execution

Only authorized proposals reach the execution layer. A denied proposal is never executed, regardless of model confidence.

3.2 Live environment result

In a reported live authority-review environment, an adversarial instruction was submitted to the system. The model's reasoning layer accepted the instruction and produced a proposal to execute it. The ExergyNet authority gate evaluated the proposal and issued a denial — the action was not executed.

This result demonstrates the authority layer's operational independence from inference. A model that accepts an adversarial instruction does not constitute a compromised system when execution requires separate authorization.

Scope of this claim: This result was observed in a specific live production-adjacent environment under conditions described in the full paper. It is not a general security guarantee. The authority layer must be correctly configured and enforced for the property to hold.

4.1 What V5 does not claim

V5 does not claim that the results generalize to arbitrary workloads, models, or infrastructure configurations. The 100M token operating point is a development characterization, not a production specification. ExergyNet is infrastructure — its properties depend on correct configuration and integration.
